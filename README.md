# WZMstring

`string` 这个小工具用来导出 COD Warzone Mobile 4.5 的游戏内文本，比如菜单、提示、物品名，结果是一份 TSV 文件。

我主要用它导出简体中文（`sch_` 开头的包）。换成其他语言的包也能用。

## 编译

只需要 C 编译器和 make：

```sh
make
```

## 使用

`data/` 里已经放好了 4.5.2（22729281）的 24 个简体中文包，直接运行：

```sh
./string -o zh.tsv data/*.ff.decoded.bin
```

这些文件是从游戏 CDN 分片中解出的 FF 流（`*.ff.decoded.bin`），解压这一步不在本工具里做。`data/SHA256SUMS` 记录了每个文件的 hash，可以用下面的命令检查：

```sh
cd data && sha256sum -c SHA256SUMS
```

如果手上有可能包含字符串名称的文件，比如 rawfile 导出目录或者 libgame 的字符串表，可以用 `-n` 加进来，`-n` 可以写多次：

```sh
./string -o zh.tsv -n rawfile/ -n libgame.strings.tsv data/*.ff.decoded.bin
```

只用 `data/` 里的包，能找回 1903 条名称；再加上 rawfile、netconststrings 和 libgame 字符串表，能找回 2176 条。

输出文件已经存在时程序会直接报错，不会覆盖。

## 输出

```
key	name	text
00007fa9374889fd		发射蚊式无人机！
066563aee26e0e02	LUA_MENU_MP/LOADOUT_8	自定义配置8
```

- `key`：游戏内部用的 64 位 hash。
- `name`：hash 对应的原始名称，找不到就留空。名称要靠 `-n` 提供的文件和包里自带的少量名称来匹配，所以大部分条目是空的。
- `text`：文本内容。文本里的换行、制表符和反斜杠写成 `\n`、`\t`、`\\`。

运行结束后，程序会在终端打印一行 `RESULT`，包括处理了多少个包、导出了多少条。

## 退出码

- `0`：全部正常。
- `1`：有包没读完，比如遇到了还不认识的资产类型，或者有文本引用找不到。TSV 照常写出，终端里会提示是哪个包。
- `2`：输入或输出出错，不会写出文件。

## 原理

每条文本的头部是 16 个字节：前 8 字节是 key，后 8 字节是文本 ID，其中第 61 位表示文本是否紧跟在后面。很多条目不带文本，只用文本 ID 引用同一个包里前面已经出现过的那句。

key 是名称经过游戏 native 路径 hash 算出来的。hash 前会先转成小写，所以找回来的名称大小写不一定和原始的一样。

## 限制

- 只导出本地化文本（type58）。Lua、GSC、rawfile 里直接写死的字符串不在范围内。
- 为了跳过排在文本前面的资产，程序还要解析几种别的类型（17、67、74、121）。碰到其他类型时，这个包就读到那里为止。
- 程序本身不校验输入文件的 hash，请用上面的 `sha256sum -c` 检查。
